# OMS 07 — Security

| Area                   | Control                                                                                                                                                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Authentication         | auth-service EdDSA JWT verified with its public key, plus a revocation check (`buildTokenVerifier`, one Redis MGET, fails closed)                                                                                                                                                                |
| Customer authorization | CUSTOMER with full scope; orders limited to own `userId` / owned farms; a foreign id → **404** (no IDOR, existence never revealed)                                                                                                                                                               |
| Admin authorization    | INTERNAL + MFA (full scope) + permission key (default deny). New keys: `orders.confirm`, `orders.configure`. Reason + audit row for confirm, reject, cancel, refund retry and resolve; **SoD** (approver ≠ requester) for refund approval and offline resolve                                    |
| Price integrity        | Prices, taxes and totals are recomputed on the server from projections and promotions; client amounts are never trusted. The payment amount is always `order.grandTotal`                                                                                                                         |
| Amount integrity       | Captured amount is compared with `grandTotal`; a mismatch sets `paymentException`, confirm is blocked and ops are alerted (R8). Refunds: Σ live ≤ captured under the payment row lock                                                                                                            |
| Idempotency            | `Idempotency-Key` + request hash stored in the DB for checkout, pay, cancel and verify; internal calls keyed by orderId / `sourceRef`; webhooks deduplicated by the provider `eventId`; inbox for every event consumer                                                                           |
| Concurrency            | Order row lock + expected status + `expectedVersion`; exactly one winner for confirm, reject, cancel, capture and timeout; promotion limits re-checked under lock; atomic sequences; one transaction per order in bulk confirm                                                                   |
| Payment gateway        | HMAC-SHA256 with `timingSafeEqual`; webhook signature over the raw body; secrets only from env (`RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`), redacted by Pino; auto-capture on; the verify API also refetches from the gateway (never trusts the client callback alone) |
| PCI / PII              | No card, bank or Aadhaar data stored; masked method fields only (FR-PAY-09). Events carry ids only. Logs carry the requestId, never tokens                                                                                                                                                       |
| Mock payments          | Only when `PAYMENT_PROVIDER=mock`; config validation **refuses mock when `APP_ENV=prod`**, and the routes are not registered otherwise                                                                                                                                                           |
| Abuse limits           | Checkout 10/min · pay and verify 20/min · cancel 10/min · admin writes 60/min · webhook body 64 KB · Joi on every input · the gateway blocks `/internal/*`                                                                                                                                       |
| Delivery OTP (F1)      | `crypto.randomInt`; HMAC (pepper) + AES-GCM at rest; TTL; attempt lock; resend cooldown and cap; owner-only view (audited); assigned-driver-only verify, with proof; never in logs or events                                                                                                     |
| Audit                  | `order_status_events` (every transition, append-only), `order_audit_log` (staff), `payment_audit_log`, `payment_webhook_events`                                                                                                                                                                  |
